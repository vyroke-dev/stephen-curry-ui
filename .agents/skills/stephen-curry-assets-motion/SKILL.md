# Art-Directed Assets + Creative Motion Freedom

1. Establish coherent brand photo/illustration/3D/video style, lighting, palette, composition, typography relation and scene continuity in DS.
2. Select asset source by fitness: supplied rights-cleared, original coded graphics, available image generator, or authorized media provider. Never assume GPT Image or Higgsfield is available or spend credits silently.
3. Produce and log asset manifests: usage, provenance, rights, file paths, sizes/optimization, review status and known generative limitations.
4. Permit bespoke motion choreography and 3D, but justify complexity by narrative/UX and implement reduced motion, keyboard/touch alternatives, frame/CPU fallbacks and cleanup.
5. Validate motion via actual playback / browser, not static design images. Check performance and behavior at entry, middle, closing and interruptions.
6. Major art-direction/DS motion-token change → Intelligent Approval Gate.

Read `../stephen-curry-ui/references/media-and-higgsfield.md` and `../stephen-curry-ui/references/motion-and-effects.md` when applicable.

**Important:** This production asset pipeline is not a replacement for the mandatory built-in image-generated UI concepts. See master `image-first-concept-pipeline.md`.


**Image-only design boundary:** All new visual design artifacts, including Brand/Design System boards and page concept visuals, must come from genuine built-in image generation, never coded drawing, HTML/CSS/SVG/React mockups or code-built screenshots. Code is authorized only to implement already approved generated-image designs. See the main image-only protocol.
