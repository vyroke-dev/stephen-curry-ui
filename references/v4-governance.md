# V4 Governance: approval, quality and revision

## Gate decisions

G0 Inspect and capability audit. G1 Deep research, evidence dossier and focused Grilling. G2 Experience architecture, verified content/brand. G3 **Seven authentic image-generated Design System visual boards, independent image-board jury and user approval**. G4 **>=3 genuinely distinct image-generated website concepts, independent concept jury and user approval**. G5 **Approval of one frozen concept with auditable evidence**. G6 Translate approved image design to executable tokens, then prototype and Codex production. G7 Browser-native full-journey QA. G8 Final blocking gates, evidence package and authorized delivery.

Each gate: `status = pending | passed | blocked | failed | waived` (waived requires actually authorized, recorded exception; critical accessibility/security defects never waived). No gate is passed merely because the assistant printed words claiming pass.

## Approval

The main coordinator may automatically move only where user already delegated authority and host enforces required permissions. Recording approval in `.scui/` JSON is not identity proof or host approval. Critical brand-direction, DS major changes, data sharing, purchases, destructive actions, scope expansion and legal permissions must go to a trusted human approval channel.

## Objective/subjective evidence

Qualitative aesthetics: jury + grounded comparative rationale and optional human blind tests. Objective issues: test evidence, screenshot paths, console traces and reproducible steps. Hard blockers: critical accessibility, security, broken core journeys, unauthorized data publication, unapproved DS drift, corrupted version mapping. Do not wash blockers away with averaged scores.

## Adaptive iteration

Each change carries `expected_improvement`, `baseline_evidence`, `new_evidence`, `regression_check`, `owner`, `resource_budget`, and `resolution`. If no progress or a regression occurs, preserve stable version, stop, escalate and replan.
