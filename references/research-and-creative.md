# Reference research and creative strategy

## Research gate (required before design or implementation)

1. Identify the project's goal, audience, industry, content structure, and strongest UX constraints. Include the existing project's live UI/design system as context, but **do not rely only on your own previous outputs** for new design research.
2. Find relevant work from real sites and legitimate case studies. Useful places to start are Awwwards, SiteInspire, Godly, respected product sites, public design systems, and directly relevant competitors. A source's visual merit or award status must be verified, not presumed.
3. For `standard`, aim for roughly 2-4 relevant examples; for `flagship`, 3-6 cross-category and category-specific examples when accessible. `micro` may reuse one relevant verified reference with a note. Counts guide effort and are not mandatory quotas.
4. Inspect the **original website** when available, not just an image gallery: typography, scale, whitespace, hierarchy, contrast, responsive layouts, scroll behavior, navigation, states, load and interaction quality. If only screenshots are available, label interactivity as **unverified**.
5. Record source URL, access date, what is demonstrably notable, one possible application, one tradeoff, and **what must not be copied**. Prefer specifics: “asymmetric serif headline with restrained supporting sans” rather than “beautiful and clean.”
6. Make a **Reference Brief** with actual sources before drafting creative concepts or touching frontend production code. If browsing is unavailable, document the limitation, use supplied source materials or verified saved references, and keep factual claims scoped to observed evidence.

## Creative synthesis

- State the **thesis** in one sentence: “For [audience], the site should feel [attribute] because [business/user goal].”
- Select 1-3 actionable design principles learned from research, then deliberately recombine them into a project-specific identity.
- Outline typographic hierarchy, layout rhythm, imagery and crop logic, visual contrast, interaction cadence, and mobile adaptation.
- Identify at least one **possible** signature element for important projects, then reject it when it hurts usability or focus.
- Compare distinct proposals by their intended audience and tradeoffs, not by how many effects they contain.
- Prefer original source content, authorized logos/media and truthful product depiction. Do not recreate another site's unique composition, branded graphics, copyrighted copy, or proprietary interface wholesale.

## Approval heuristic

| Work | Default creative gate |
| --- | --- |
| Micro fix within established system | Execute after checking existing patterns and references |
| Standard new page or feature | Propose concise direction; ask only when genuinely ambiguous |
| Flagship identity, expensive media, radical redesign | Show 2-3 materially different concepts; approval before irreversible commitment unless explicitly delegated |

If the user prefers autonomy, make the choice, record the reasoning and continue. **Approval is for decisions with real impact, not a ritual at every step.**

## Red flags

- Unsourced “Awwwards winner” claims; inaccessible sites described as observed.
- Visual exploration consisting only of color swaps.
- Premature coding before inspiration research or a direction is chosen.
- Derivative imitation of one reference instead of synthesis.
- Reference research used to ignore the existing brand, customers or task.
