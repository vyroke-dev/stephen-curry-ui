# Experience Architecture

1. Inspect the existing routes, users, tasks, success criteria, decision points, and content relationships relevant to the request.
2. For a new site or major redesign, map the sitemap, critical journeys, navigation, content hierarchy, and important empty, loading, error, and success states. For a contained change, map only the affected flow.
3. Keep content statuses clear: `verified | user_supplied | pending | placeholder`. Do not invent quotes, products, prices, or business facts.
4. Infer device priorities from the brief and evidence, and state the recommendation. Ask the user only when desktop/mobile/adaptive priority materially changes the solution and remains unclear.
5. Design the journey across entry, middle, ending, routes, and interruptions when scope warrants; functional products need clear task flow rather than theatrical pacing.
6. Document `experience-architecture.md` and the content/device decisions for substantial work; avoid creating an artifact for a one-state patch.

Read `../stephen-curry-ui/references/experience-direction.md` when planning a whole experience.
