# Research-Driven Experience Architecture

1. Map users, intent, critical jobs, success criteria, primary routes, decision points, content relationships, navigation and conversion/resolution.
2. Create sitemap, critical user flows, content hierarchy and content model with statuses `verified | user_supplied | pending | placeholder`. Never publish invented quotes, products, pricing or facts.
3. Research device context then **ask user** which project-specific priority (desktop/mobile/adaptive) they need, with reasoned recommendation; do not apply a universal policy.
4. Create experience arc across entry, middle, ending, states and routes; adapt theatrical pacing to functional products.
5. Validate long/short text, localization, missing/error/empty states, keyboard/touch and accessibility constraints.
6. Document `experience-architecture.md`, `content-model.json` and device decision.

**Gate:** approved core structure precedes formal page visual design, but narrative composition can vary across concepts. Load `../stephen-curry-ui/references/experience-direction.md`.


**Image-only design boundary:** All new visual design artifacts, including Brand/Design System boards and page concept visuals, must come from genuine built-in image generation, never coded drawing, HTML/CSS/SVG/React mockups or code-built screenshots. Code is authorized only to implement already approved generated-image designs. See the main image-only protocol.
