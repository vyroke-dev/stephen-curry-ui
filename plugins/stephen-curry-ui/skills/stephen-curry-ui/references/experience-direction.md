# Experience Direction Engine — the new creative core

## Treat the website as a composed experience

Art-direction quality is not constrained to pixels. Build a complete **experience blueprint** with three linked scores:

- **Narrative score:** what visitors understand and feel at each stage; primary message, proof, payoff, action.
- **Motion score:** how the camera, text, objects, interactions and transitions move; when to slow down, accelerate, pause, reveal or invert expectation.
- **State score:** what can be clicked, dragged, held, scrolled, dismissed, revisited, muted, interrupted or accessed without a pointer.

The scores should reinforce one shared motif. If typography behaves like a mechanical receipt but the transitions resemble a sci-fi portal with no conceptual tie, challenge the inconsistency.

## Chapter map for a flagship marketing site

This is a **design scaffold**, not a mandatory fixed sequence:

| Experience beat | Visitor intention | Design/directing requirement | Evidence needed |
| --- | --- | --- | --- |
| Arrival / preload | Can I enter and understand what's coming? | Meaningful fast first paint; optional user-controlled intro; no dead lock | First interaction video + alternate route |
| Overture | What is this? | Immediate compelling premise and visual grammar, but accessible content | Desktop/mobile opening |
| World-building | Where am I and what does it mean? | Establish depth, subject, categories, tempo; editorial rhythm | Mid-page, not hero-only |
| Interaction turn | What can I do? | A purposeful gesture with affordance, feedback, reward and exit | Gesture-state capture |
| Escalation / proof | Why should I care or trust it? | Deepen content and vary composition while retaining identity | Content usability + motion |
| Payoff / reveal | What's the memorable resolution? | A meaningful signature moment, not a decorative jump scare | End-to-end recording |
| Decision / CTA | What should I do next? | Clear action; smooth return to normal readable UI when necessary | Functional flow test |
| Closing / return | Does it end intentionally? | Designed footer, route bridge, optional replay or explore-again | Bottom capture, route test |

For applications/dashboard: replace theatre with **task narrative** (orientation → work → feedback → recovery → success), still design the complete set of states and transitions.

## The Experience Arc quality test

At every chapter or major route ask:

1. **Purpose:** what new information, choice or emotional shift occurs?
2. **Differentiation:** why doesn't it look like a generic template section?
3. **Continuity:** which motif, object, story beat, interaction state or typography bridges from the previous chapter?
4. **Input:** what action or natural progression moves the visitor through it?
5. **Recovery:** can the visitor reverse, skip, re-enter, back-navigate, pause, or revisit the moment?
6. **Responsive adaptation:** what changes fundamentally on a phone rather than shrinking the scene?
7. **Performance:** can this chapter appear without a surprise shader compilation, GPU upload hitch, or huge video download?

A failed chapter is a **quality fault** even if it lies below the fold. Never deliver a remarkable hero followed by repetitive cards, generic numbers and a default footer.

## Motif and effect coherence

Create an **experience grammar** before animations:

- **Spatial:** movement along a path, orbit, push/pull, gravity, depth planes.
- **Typographic:** tracking, split/recombine, reveal direction, text as an interactive object.
- **Material:** glass, paper, metal, liquid, noise, fabric, light; constraints on how it reacts.
- **Temporal:** acceleration, rests, delays, sound cues, cinematic holds, transition timing.
- **Input:** scroll, drag, tap, hold, keyboard, focus; same action should produce consistent feedback.
- **Sonic (optional):** voice, ambient loop, cues, opt-in/out, mute, sync to rendered frame.

Add a new effect only if it is grammatically connected, or its contrast is **deliberate and justified**. Visual richness does not require maximal motion density.

## Structured evaluation: avoid shallow concept comparisons

When comparing concepts, use a brief weighted rationale for audience fit, originality, whole-journey flow, interaction coherence, feasible production and accessibility. Do not over-trust subjective 0–100 scores. Assess technical feasibility from existing evidence before selecting a direction; implement PoCs only after approved generated-image design, and request reapproval of changed visuals.

## Red flags that block approval

- A story described only through hero, gallery and CTA.
- All chapters have the same fade-up and marquee gimmick.
- Repeated unrelated effects, random cursor circles, arbitrary lens blur and scroll hijacking.
- Impossible image-generated UI rendered as one bitmap.
- “Signature moment” that never advances the user's comprehension.
- Full experience only on desktop; mobile becomes static afterthought.
- No ending, no route navigation, no recovery from interaction gating.


**Version 4.2 precedence:** Any legacy suggestion to use code-rendered visuals for creative exploration or Design System design is superseded. All formal design visuals must be created by genuine image generation; coded work is implementation only after visual approvals.
