# Design knowledge, privacy and provenance

**Two-tier memory:** keep project briefs, references, original designs, produced assets and QA in that project's repo private by default. Share only **generalizable, verified and non-sensitive patterns** to an actual writable shared location with consent.

- Suggested project folder: `docs/stephen-curry-ui/`. Adapt to repo conventions and ignore security-sensitive files.
- Suggested shared local location: `~/.agents/stephen-curry-ui/knowledge/`, **only if** the user's runtime actually supports it and there is standing permission or explicit approval.
- Never add customer logos, brand secrets, API keys, internal data, private URLs, purchased licensed assets or client-specific code to shared cross-project records without clear rights and approval.
- Store source URLs with observed facts and dates; distinguish creator technical explanations from direct testing and unverified assumptions. Recheck old references on new projects.
- Promotion rule: observation/test → bounded lesson → generalized conditions → license/privacy check → user consent → actual file write → verify stored artifact. If the write fails, report it; do not claim the AI “learned” across projects.
