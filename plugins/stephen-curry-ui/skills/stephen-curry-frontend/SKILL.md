# Design Engineering

1. Inspect the relevant source, dependencies, routes, current Design System, and repository instructions. Reuse correct architecture and accessible primitives.
2. Follow the user's chosen or approved direction. For focused work, apply existing tokens and behavior; obtain approval before high-impact migrations or unresolved strategic changes.
3. Implement complete behavior for the requested scope, including relevant navigation, content, loading/error/empty states, actions, and responsive layouts. A full-site build must cover the full journey, not only its hero.
4. Use semantic HTML, keyboard and touch support, visible focus, usable contrast and zoom, and reduced-motion behavior appropriate to the interaction.
5. Preserve input validation, data safety, privacy, security headers, SEO, and asset budgets relevant to the project. Never expose secrets or publish unverified content.
6. Run the smallest meaningful checks requested by the project and report exact results. Do not describe an unverified implementation as production-ready.
7. If multiple agents implement code, assign non-overlapping file ownership and an explicit integration owner; review the combined diff and retest affected behavior.

Read `../stephen-curry-ui/references/prototyping-and-engineering.md` and `../stephen-curry-ui/references/delivery-standards.md` when the task needs their detailed guidance.
